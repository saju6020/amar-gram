FINDINGS
- [LOW] web/app/(staff)/staff/shop/products/page.tsx:51 (with web/components/staff-shop/ProductBulkActions.tsx:89-105). The page passes `onBulkStatus` to every role. A ProductsView-only user (Reception or Inventory) therefore sees the select column and the Publish and Hide from shop bar, but the server requires `Shop.ProductsManage` (ShopManager or Administrator; StaffProductsController.cs:284-285, ActionRoles.Shop.cs:14). The click is refused with a 403, which shows as an error sentence, and nothing changes. The same holds for the certificate uploader on Food & labelling: FilePurposeAccess.cs:174 maps `OrganicCertificate` to `ProductsManage`, so the upload fails closed. This matches the staff-shop area's existing convention, which has no client-side role gating, so it is a presentation issue and not an authorisation gap. The shop mock models no roles either (mocks/handlers/shop/staff.ts:17), so U47 cannot exercise the 403. Remediation, optional: pass `onBulkStatus` only for `['ShopManager','Administrator']`, and add a 403 to the bulk-status mock.
- [LOW] web/mocks/handlers/shop/staff.ts:608-617 is test fidelity only. The mock accepts a new `organicCertificateFileId` when the file was uploaded with purpose `OrganicCertificate` and no other product uses it. The server also requires that the file is the caller's own upload and that it is attached within `FileRules.AttachWindow` (30 minutes) (SetFoodDetailsCommandHandler.cs:228-233, `IsEligibleForAttach(..., UserId, now, AttachWindow)`). A mock run therefore accepts an old file or another user's file that the server refuses with `InvalidCertificateFile`. Production is unaffected. Remediation: record the uploader and the upload time in `uploadBehavior.ts`, check both in the mock, and add one U47 case.
- [LOW] web/app/(staff)/staff/procurement/consignments/page.tsx:63. The raw `arrivingWithinDays` query value is echoed into the sentence "Showing consignments arriving in the next {value} days…". A crafted staff link such as `?arrivingWithinDays=…any words…` displays attacker-chosen words in the page. React escapes the value, so this is text spoofing and not markup injection. The server refuses anything outside the integers 1-90 (400 `InvalidQuery`), so the list itself never shows wrong data. The impact is content spoofing to a signed-in staff member only. Remediation: show the sentence only when the value matches `^[1-9]\d?$` and is ≤ 90, and otherwise ignore the parameter.
- [LOW] web/public/mockServiceWorker.js:1 is carried unchanged from HO-P5-WIRING-S0-SECURITY. S3 does not touch it.
